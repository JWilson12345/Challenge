Challenge Setup Guide

Follow this guide in your web browser using the Firebase Console and GitHub website. It explains the exact places to click and what values to copy for the Challenge app.

What You Need

  • A Google account for Firebase.
  • A GitHub account.
  • This project uploaded to a GitHub repository.
  • The files already included in this project: firestore.rules, storage.rules, firestore.indexes.json, and .github/workflows/deploy-pages.yml.

Firebase web config values are not private passwords. They identify your Firebase project to the browser app. Security comes from Firebase Auth, Firestore rules, Storage rules, and admin permissions.

1. Create the Firebase Project

  1. Open Firebase Console.
  2. Select Add project.
  3. Project name: Challenge.
  4. Google Analytics: choose Disable unless you specifically want analytics.
  5. Finish the project creation flow and wait for Firebase to open the project dashboard.

2. Add a Web App and Copy the Config

  1. In Firebase project overview, select the Web icon. It looks like </>.
  2. App nickname: Challenge Web.
  3. Do not enable Firebase Hosting. The app is intended for GitHub Pages.
  4. Select Register app.
  5. Firebase will show a code snippet containing firebaseConfig. Copy these values:
Firebase field GitHub secret name
apiKeyVITE_FIREBASE_API_KEY
authDomainVITE_FIREBASE_AUTH_DOMAIN
projectIdVITE_FIREBASE_PROJECT_ID
storageBucketVITE_FIREBASE_STORAGE_BUCKET
messagingSenderIdVITE_FIREBASE_MESSAGING_SENDER_ID
appIdVITE_FIREBASE_APP_ID

If you leave this screen, you can find the same config later in Firebase: Project settings -> General -> Your apps -> SDK setup and configuration -> Config.

3. Enable Login Accounts

  1. In Firebase, open Build -> Authentication.
  2. Select Get started.
  3. Open the Sign-in method tab.
  4. Select Email/Password.
  5. Turn on Email/Password. You do not need “Email link”.
  6. Select Save.

4. Create Firestore Database

  1. In Firebase, open Build -> Firestore Database.
  2. Select Create database.
  3. Choose Production mode.
  4. Choose the nearest location to your group. For the UK, a Europe location is usually sensible.
  5. Select Enable.

Paste Firestore Rules

  1. Inside Firestore Database, open the Rules tab.
  2. Open the project file firestore.rules.
  3. Copy everything in that file.
  4. Paste it into the Firebase Rules editor, replacing the existing rules.
  5. Select Publish.

Important first-admin note: the app’s Settings -> Admin password flow sets your user as admin after you enter password 67. If Firebase rules stop that first admin update, temporarily allow your own user document update in the Firebase Rules tab, unlock admin once, then put the normal rules back. For a cleaner long-term setup, manually set admin: true on your user document in Firestore after creating your account.

5. Enable Firebase Storage

  1. In Firebase, open Build -> Storage.
  2. Select Get started.
  3. Choose the same region family as Firestore where possible.
  4. Finish the setup flow.

Paste Storage Rules

  1. Inside Storage, open the Rules tab.
  2. Open the project file storage.rules.
  3. Copy everything in that file.
  4. Paste it into the Firebase Storage rules editor.
  5. Select Publish.

6. Add Your Website Domain to Firebase Auth

  1. In Firebase, open Build -> Authentication -> Settings.
  2. Find Authorized domains.
  3. Add your GitHub Pages domain. It usually looks like your-github-name.github.io.
  4. If your app is inside a project URL such as your-github-name.github.io/challenge, still add only the domain: your-github-name.github.io.

7. Put the Firebase Values into GitHub

  1. Open your GitHub repository in a browser.
  2. Open Settings -> Secrets and variables -> Actions.
  3. Select New repository secret.
  4. Create these six secrets, using the values from the Firebase config table:
  • VITE_FIREBASE_API_KEY
  • VITE_FIREBASE_AUTH_DOMAIN
  • VITE_FIREBASE_PROJECT_ID
  • VITE_FIREBASE_STORAGE_BUCKET
  • VITE_FIREBASE_MESSAGING_SENDER_ID
  • VITE_FIREBASE_APP_ID

Add them one at a time. The secret name must match exactly, including capital letters and underscores.

8. Turn on GitHub Pages

  1. In the GitHub repository, open Settings -> Pages.
  2. Under Build and deployment, set Source to GitHub Actions.
  3. Open the Actions tab of the repository.
  4. Run or wait for the workflow named Deploy to GitHub Pages.
  5. When the workflow finishes, return to Settings -> Pages to see the published website URL.

9. First App Setup

  1. Open your GitHub Pages website URL.
  2. Create your account.
  3. Open Settings -> Admin.
  4. Enter admin password 67.
  5. Create your first challenge.
  6. Set its status to Active.
  7. Ask another friend to create an account and submit a score from their own device.

10. What to Test Before Inviting Everyone

  • You can create an account and stay logged in after refreshing.
  • You can enable admin mode with password 67.
  • You can create one active challenge.
  • You can submit a score with a title and description.
  • You can upload one photo and multiple photos.
  • A second user can see the same challenge and leaderboard.
  • Votes and comments update for both users.
  • Finalising a challenge moves it into history and awards overall points.

Troubleshooting

The app says Firebase setup required

One or more GitHub repository secrets is missing or spelled differently from the required names. Check all six secrets and redeploy with GitHub Actions.

Login fails

Check that Email/Password sign-in is enabled and that your GitHub Pages domain is listed under Firebase Authentication authorized domains.

Posts or admin actions fail

Check Firestore rules, confirm your user document has admin: true, and confirm the challenge is active.

Images do not upload

Check Firebase Storage is enabled, Storage rules are published, and the image file is not extremely large.
